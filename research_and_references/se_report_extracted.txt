Abstract 
India records 1.68 lakh road accident deaths annually — one life lost every four minutes — making it the 
country with the highest road fatality rate globally. Critically, 50% of these deaths are preventable during the 
'Golden Hour' (the first 60 minutes post-trauma), yet average ambulance response times of 35–90 minutes 
render this window largely unused. Bystanders, already present at accident scenes, hesitate to help due to fear 
of legal consequences, despite India's Good Samaritan Law (2019) — a law 94% of Indians remain unaware 
of. 
ResQ Network is an AI-powered emergency response platform that bridges this gap: automatic crash 
detection via smartphone sensors, GPS-based dispatch to the nearest trained bystander within seconds, 
multilingual AI voice guidance for on-scene first aid, and blockchain-based legal protection for responders. 
Hospitals are pre-notified with victim data before ambulance arrival, saving 10–15 minutes. 
This report presents the complete Software Engineering documentation — feasibility analysis, requirements 
engineering (IEEE IEENSVR), system design with all UML and data diagrams, construction and testing 
strategy, risk analysis, SQA, configuration management, and project metrics — covering the full SDLC for 
ResQ Network. 
Keywords: Emergency Response, Golden Hour, AI Dispatch, Good Samaritan Law, Bystander Activation, 
Blockchain, Mesh Network.

Chapter 1: Introduction 
1.1 Overview of the Project 
ResQ Network is an AI-powered emergency response platform designed to address India's road accident 
fatality crisis. India records approximately 1.68 lakh road accident deaths every year (MoRTH 2022), the 
highest road fatality rate globally — one death every four minutes. 
The core insight: a trained bystander already at the accident scene can provide life-saving first aid far faster 
than any ambulance. ResQ Network harnesses this potential by combining AI, GPS dispatch, multilingual 
voice guidance, and legal protection to create the world's first proactive bystander-first emergency response 
system for India. 
1.2 Problem Background 
• 
Bystander Hesitation: 78% want to help but fear legal trouble; 94% unaware of Good Samaritan 
Law (2019). 
• 
Slow Ambulance Response: 35–90 minute average ETA. Golden Hour (first 60 minutes) is 
routinely lost. 
• 
Result: 71% of accident victims die before reaching hospital — all preventable deaths. 
1.3 Objectives 
1. Detect accidents automatically via smartphone/wearable sensors. 
2. Dispatch the nearest trained ResQ Responder within seconds via GPS-based AI dispatch. 
3. Guide the responder on-scene in their local language via AI voice + AR. 
4. Pre-notify the hospital with victim data before ambulance arrival. 
5. Provide blockchain-based legal protection to every responder. 
1.4 Scope 
• 
Flutter mobile app (victim + responder + hospital + admin modes). 
• 
AI backend for crash detection, scene assessment, dispatch, and hotspot prediction. 
• 
P2P mesh network for zero-signal highway operation. 
• 
Integration with 112 India emergency services and hospital systems (HL7 FHIR). 
• 
Blockchain layer (Hyperledger Fabric) for tamper-proof action logs.

Chapter 4: System Design 
This chapter presents the complete visual system design of ResQ Network using standard software

4.1 System Architecture 
ResQ Network is built on a four-layer architecture: Presentation (Flutter mobile + web), Application (Firebase 
Cloud Functions + AI Engine), Data (Firestore + Hyperledger Fabric), and Edge (Meshtastic mesh network 
for offline operation).

relationships between them. Primary keys are shown in red; foreign keys in grey. Relationships are labelled 
with cardinality (1:1, 1:N, M:N).

Figure 2: ResQ Network — Entity Relationship (ER) Diagram 
 
Key Relationships: 
• 
USER ─── 1:1 ─── MEDICAL_VAULT: Each registered user has exactly one medical vault. 
• 
USER ─── 1:N ─── INCIDENT: A victim user can be involved in multiple incidents over time. 
• 
INCIDENT ─── M:N ─── RESPONDER via ASSIGNMENT: Multiple responders can be 
dispatched to one incident. 
• 
ASSIGNMENT ─── 1:N ─── ACTION_LOG: Every action taken during an assignment is 
logged individually. 
• 
ASSIGNMENT ─── 1:1 ─── CERTIFICATE: One legal certificate is issued per completed 
assignment. 
• 
HOSPITAL ─── 1:N ─── AMBULANCE: Each hospital manages multiple ambulances.
